# 인도어 피클볼장 통합 예약 플랫폼 MVP PRD

2026-11-16 · 오승민

## 개요

MVP의 목표는 서울·수도권 인도어 피클볼장 10곳을 무료 운영자 도구로 온보딩하고, 이용자가 한 앱에서 30분 단위로 코트를 검색·예약·결제하게 만드는 것이다.

**문제.** 한국 인도어장은 네이버 예약, 카카오톡 오픈채팅, 전화, 엑셀 등으로 예약을 제각각 받는다. 이용자는 빈 코트를 찾으려고 여러 채널을 돌아다니고, 운영자는 노쇼와 수기 관리에 시간을 쓴다.

**전략.** 공급(시설)을 먼저 잡는다. 운영자에게 CourtReserve급 관리 도구를 무료로 주고, 그 데이터가 그대로 이용자 앱의 통합 검색이 된다. 수익은 이용자 결제 건당 수수료(가정: 결제액의 3~5%)로 만든다.

**CourtReserve 대비 한국 재설계 포인트**

| 항목 | CourtReserve (미국) | 이 플랫폼 (한국) |
|---|---|---|
| 대상 | 클럽 1곳의 회원 운영 SaaS | 전 시설을 묶는 이용자 마켓플레이스 + 운영자 도구 |
| 과금 | 시설이 월 구독료 지불 | 시설 무료, 이용자 결제 수수료 |
| 회원 모델 | 멤버십 가입이 전제 | 비회원 일반 이용자가 대부분, 시설 회원은 선택 |
| 로그인 | 이메일/비밀번호 | 카카오 로그인 |
| 결제 | 카드(Stripe 등) | 토스페이먼츠(카드, 간편결제, 계좌이체) |
| 알림 | 이메일, 푸시 | 카카오 알림톡 |
| 예약 단위 | 시설 설정(보통 30·60·90분) | 30분 슬롯 고정, 최소 이용시간은 시설 설정 |
| 노쇼 대응 | 회원 등급·벌점 | 선결제(예약금) + 취소 수수료 구간 |

**MVP 성공 지표 (출시 후 3개월)**

- 공급: 입점 승인 시설 10곳, 그중 7곳이 주 1회 이상 운영자 도구 사용
- 수요: 월 예약 완료 1,000건, 재예약률 40% 이상(첫 예약 후 30일 안에 다시 예약한 이용자 비율)
- 품질: 노쇼율 5% 이하, 결제 실패율 2% 이하

위 수치는 기획용 초기 목표치이며, 파일럿 시설 인터뷰 후 조정한다.

## 1. MVP 기능 목록

MVP는 "코트 검색 → 30분 단위 예약 → 토스 결제 → 알림톡 → 취소/노쇼 처리"와 이를 운영자가 설정하는 도구만 만든다. 오픈플레이는 요청 범위에 따라 넣되, 가장 단순한 형태(정원제 참가 + 결제)로 제한한다.

### 이용자 앱

| 기능 | MVP (꼭 필요) | 나중에 |
|---|---|---|
| 계정 | 카카오 로그인, 휴대폰 번호 수집(알림톡용), 이용약관·개인정보 동의 | 네이버·애플 로그인, 프로필(DUPR 레벨, 선호 지역) |
| 검색 | 지역(시/구) + 날짜 + 시작 시간 + 이용 시간으로 빈 코트 검색, 목록 보기 | 지도 보기, 내 주변 거리순, 가격·편의시설 필터 |
| 시설 상세 | 사진, 주소, 코트 수·바닥재, 운영시간, 가격표, 취소 규정, 30분 단위 시간표 | 리뷰·별점, 즐겨찾기 |
| 예약 | 연속 슬롯 선택(최소·최대 이용시간 검증), 예약 규칙 검증, 결제 중 10분 슬롯 선점 | 정기 예약(매주 반복), 대기 예약(웨이팅) |
| 결제 | 토스페이먼츠 결제위젯(카드·간편결제), 전액 선결제, 취소 시 규정에 따른 자동 부분환불 | 더치페이(일행 분할 결제), 쿠폰, 포인트, 정기권 |
| 내 예약 | 예약 목록(예정/지난), 취소(환불액 미리 보기), 영수증 | 일행 초대 링크, 예약 양도 |
| 오픈플레이 | 시설이 개설한 세션 목록, 정원제 참가 신청 + 결제, 참가 취소 | 레벨 제한, 대기열, 로테이션 매칭 |
| 알림 | 알림톡: 예약 확정, 취소·환불, 이용 전날 리마인드 | 앱 푸시, 빈자리 알림 |

| 회원 관리 | 이용 고객 목록(이름, 연락처, 이용 횟수, 노쇼 횟수), 메모, 예약 차단 | 멤버십·회원권 판매, 단체 메시지 |
| 매출·정산 | 기간별 매출, 수수료, 정산 예정액 조회 | 가동률 리포트, 세금계산서 자동 발행 |
| 알림 | 신규 예약·취소 알림톡(운영자 번호) | 모바일 운영자 앱 |

### 플랫폼 관리자 (웹)

| 기능 | MVP (꼭 필요) | 나중에 |
|---|---|---|
| 시설 승인 | 입점 요청 목록, 사업자등록증 확인, 승인·반려·정지 | 자동 사업자 진위 확인 API |
| 정산 | 시설별·기간별 결제·환불·수수료·지급액 조회, 지급 완료 처리 | 토스 지급대행 자동화 |
| 운영 | 예약·결제 검색, 환불 수동 처리(CS) | 대시보드, 분쟁 관리 |

### 노쇼 방지 기본 정책 (MVP)

예약금을 따로 받지 않고 **전액 선결제 + 취소 시점별 환불률**로 시작한다. 한국 스포츠시설 예약에서 익숙한 방식이고, 현장 잔금 결제를 없애 정산이 단순해진다. 시설은 아래 기본값을 바꿀 수 있다.

| 취소 시점 | 기본 환불률 |
|---|---|
| 이용 48시간 전까지 | 100% |
| 48~24시간 전 | 50% |
| 24시간 이내 | 0% |
| 노쇼(운영자 처리) | 0% + 노쇼 1회 기록 |

노쇼 3회 누적 시 해당 시설 예약을 30일 제한하는 규칙은 "나중에"로 둔다. 결제 완료 후 10분 이내 취소는 이용 시작 전이라면 항상 전액 환불해 실수 예약 불만을 막는다.

## 3. 핵심 사용자 흐름

### A. 이용자 코트 예약 (U03 → U08)

1. **검색(U03):** 지역 "서울 성동구", 날짜, 시작 19:00, 이용 90분을 고른다. 로그인 없이도 검색은 가능하다.
2. **결과(U04):** 19:00~20:30 3개 슬롯이 모두 비어 있는 코트가 1개 이상인 시설만 보여준다.
3. **시간표(U05):** 코트 × 30분 그리드에서 연속 슬롯을 탭한다. 최소·최대 이용시간을 벗어나면 버튼이 비활성화된다.
4. **로그인 체크:** 비로그인이면 카카오 로그인(U01→U02) 후 선택한 슬롯으로 돌아온다.
5. **선점(U06):** 서버가 규칙을 검증하고 booking(`held`)을 만든다. 10분 타이머가 돌고, 취소 규정 동의가 필수다. 다른 사람이 먼저 잡았으면 "방금 예약된 시간" 안내 후 U05로 돌아간다.
6. **결제(U07):** 토스 위젯 → 성공 리다이렉트 → 서버가 금액 대조 후 승인 API 호출 → booking `confirmed`.
  - 실패·이탈: booking `held` 유지, 타이머 내 재시도 가능. 10분 만료 시 슬롯 해제(크론 1분 간격). 결제 승인 API를 호출하기 직전에 서버가 booking이 아직 held이고 hold_expires_at 전인지 다시 확인한다. 이미 만료됐으면 승인하지 않고 "선점 시간이 지났어요" 안내 후 U05로 돌려보낸다.
7. **완료(U08):** 이용자에게 예약 확정 알림톡, 운영자에게 신규 예약 알림톡. 이용 전날 20:00에 리마인드 알림톡.
8. **취소(U10):** cancellation_tiers로 환불액을 미리 보여주고, 확인 시 토스 부분취소 → 슬롯 해제 → 취소 알림톡.

### B. 운영자 입점·코트 등록 (O01 → O09)

1. **가입(O01):** 카카오 로그인 후 "시설 운영자로 시작" 선택.
2. **입점 신청(O02):** 시설명·주소·사업자등록번호·등록증·정산 계좌 제출 → facilities `pending`.
3. **승인 대기 중 설정:** 승인 전에도 O04~O08 설정을 미리 할 수 있다. 대시보드(O03) 체크리스트가 순서를 안내한다.
4. **코트 등록(O05):** 코트 수 입력 → "A코트, B코트…" 자동 생성, 이름·바닥재 수정.
5. **운영시간(O06):** 요일별 오픈·마감을 30분 단위 드롭다운으로. "평일 일괄 적용" 버튼.
6. **가격(O07):** 평일/주말 × 시간대 표에 30분당 가격 입력. 운영시간 중 가격이 빈 구간이 있으면 저장 불가.
7. **규칙(O08):** 사전예약 14일, 1일 최대 120분, 1회 60~120분, 취소 규정(기본값 채워짐)을 확인·수정.
8. **승인(A02):** 플랫폼 관리자가 승인 → `approved` → 운영자에게 승인 알림톡, 이용자 검색에 노출.
9. **운영(O09):** 예약 캘린더에서 전화 예약을 수동 등록하고, 이용 당일 노쇼를 처리한다.

## 4. 데이터베이스 테이블 초안

PostgreSQL 기준 18개 테이블이다. 핵심은 예약을 30분 슬롯 단위 행(`booking_slots`)으로 쪼개고, `(court_id, slot_start)`에 유니크 제약을 걸어 동시 예약·중복 예약을 DB 레벨에서 막는 것이다. 모든 금액은 원 단위 정수, 모든 시각은 `timestamptz`(표시는 Asia/Seoul)로 한다.

### 계정·시설

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `users` | id, kakao_id(UQ), name, phone, email, role(`user`/`admin`), marketing_agreed, created_at | 운영자도 같은 users 행, 권한은 facility_staff로 |
| `facilities` | id, name, address, region_sido, region_sigungu, lat, lng, phone, description, photos(jsonb), amenities(jsonb), business_no, bank_account(암호화), status(`pending`/`approved`/`rejected`/`suspended`), approved_at, approved_by | 검색은 region + status=approved |
| `facility_staff` | id, facility_id, user_id, role(`owner`/`staff`) | MVP는 owner 1명, 구조만 미리 |
| `courts` | id, facility_id, name("A코트"), surface, sort_order, is_active |  |

### 운영 설정

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `operating_hours` | id, facility_id, weekday(0~6), open_time, close_time | 30분 배수만 허용 (CHECK) |
| `blackouts` | id, facility_id, court_id(null=전체), start_at, end_at, reason | 휴무일·임시 차단·대관 |
| `price_rules` | id, facility_id, day_type(`weekday`/`weekend`/`holiday`), start_time, end_time, price_per_30min | 시간대별 가격, 겹침 금지. MVP 화면(O07)은 평일/주말만 다루므로 holiday는 공휴일 가격 오픈 이슈가 정해진 뒤 사용 |
| `booking_policies` | facility_id(PK), advance_days, max_minutes_per_day, min_minutes_per_booking, max_minutes_per_booking, hold_minutes(기본 10) | 1시설 1행 |
| `cancellation_tiers` | id, facility_id, hours_before, refund_percent | 예: (48,100), (24,50), (0,0) |

### 예약·오픈플레이

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `bookings` | id, booking_no, user_id(null=수동), facility_id, court_id, start_at, end_at, total_amount, status(`held`/`confirmed`/`cancelled`/`completed`/`no_show`), source(`app`/`manual`/`open_play`), hold_expires_at, guest_name, guest_phone, cancelled_at, cancel_reason, created_at | 수동 예약은 guest_* 사용 |
| `booking_slots` | id, booking_id, court_id, slot_start | **UQ(court_id, slot_start)**, 취소·만료 시 행 삭제 |
| `open_play_sessions` | id, facility_id, court_ids(int[]), title, start_at, end_at, capacity, fee, status | 세션 시간의 코트 슬롯은 booking(source=`open_play`)으로 잡아 둔다. 코트가 여러 개면 코트마다 booking을 1건씩 만든다(bookings.court_id는 단일 값) |
| `open_play_participants` | id, session_id, user_id, payment_id, status(`joined`/`cancelled`) | UQ(session_id, user_id) |

### 결제·정산·알림·회원

| 테이블 | 주요 컬럼 | 비고 |
|---|---|---|
| `payments` | id, order_id(UQ), booking_id / participant_id, user_id, amount, method, toss_payment_key, status(`ready`/`done`/`partial_cancelled`/`cancelled`/`failed`), approved_at, raw(jsonb) | 토스 승인 응답 원본 보관 |
| `refunds` | id, payment_id, amount, refund_percent, reason(`user_cancel`/`facility_cancel`/`admin`), toss_cancel_tx, created_at | 부분취소 이력 |
| `settlements` | id, facility_id, period_start, period_end, gross_amount, refund_amount, fee_amount, payout_amount, status(`pending`/`paid`), paid_at | 주 1회 생성(가정) |
| `facility_customers` | id, facility_id, user_id, visit_count, no_show_count, memo, is_blocked | 운영자의 "회원 관리" |
| `notifications` | id, user_id / phone, template_code, booking_id, status(`sent`/`failed`), sent_at, vendor_msg_id | 알림톡 발송 이력·재발송 |

**예약 규칙 검증 순서 (서버, 하나의 트랜잭션)**

1. 시작·종료가 30분 경계인지, 운영시간 안이고 blackout과 겹치지 않는지
2. 이용시간이 min~max_minutes_per_booking 안인지
3. 오늘 + advance_days 이내인지
4. 같은 이용자의 같은 시설·같은 날 confirmed+held 합계가 max_minutes_per_day 이하인지
5. facility_customers.is_blocked가 아닌지
6. booking(held) + booking_slots INSERT — 유니크 제약 위반 시 "이미 예약된 시간" 응답. INSERT 전에 같은 슬롯의 만료된 held 예약을 먼저 정리해, 크론이 돌기 전(최대 1분) 빈 슬롯이 막혀 보이지 않게 한다
7. 금액은 price_rules로 슬롯별 합산(클라이언트 금액은 믿지 않음)

## 5. 오픈 이슈

- 수수료율과 부담 주체: 시설 정산액에서 떼는가, 이용자에게 예약 수수료로 붙이는가 — 파일럿 시설 인터뷰로 결정. 토스페이먼츠 결제 수수료(PG 수수료)를 누가 부담하는지도 함께 정한다
- 정산 구조: 플랫폼이 대금을 받아 지급하면 전자금융업(PG) 이슈가 생길 수 있음. 토스페이먼츠 지급대행(마켓플레이스) 상품 사용 가능 여부와 심사 조건 확인 필요
- 알림톡 발송 대행사(카카오 비즈니스 채널 + 딜러사) 선정과 템플릿 6종 심사(이용자: 예약 확정, 취소·환불, 리마인드 / 운영자: 신규 예약, 취소 / 입점 승인)
- 기존 네이버 예약·전화 예약과의 이중 예약: MVP는 운영자 수동 등록으로 대응, 외부 캘린더 연동은 나중에
- 공휴일 가격(주말가 적용 여부)과 공휴일 데이터 소스
- 우천·시설 사정 취소 시 환불 정책(시설 취소는 항상 100%로 가정)
- 오픈플레이 참가 취소 환불 규정(코트 예약 취소 규정을 그대로 쓸지)과, 최소 인원이 안 찼을 때 세션 취소·전액 환불 기준
- 정산 지급이 끝난 뒤 생긴 환불(시설 사정 취소 등)을 다음 정산에서 차감하는 방식

**다음 단계:** 파일럿 후보 시설 3~5곳에 이 문서의 운영자 기능·취소 규정·수수료를 보여주고 피드백을 받은 뒤, O09 예약 캘린더와 U05 시간표 화면부터 와이어프레임을 만든다.
